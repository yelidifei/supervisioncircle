# 部署与网址

## 目前的结构

GitHub 仓库：<https://github.com/yelidifei/supervisioncircle>

运行环境：Sites 托管 React 页面与服务端接口，D1 保存小组和每月投票。入口需要设置为公开，导师才能免登录；进入具体小组仍需要完整的共享链接。

本仓库不放实际共享链接或管理链接，以免把参与权限或管理权限公开给仓库访客。请从管理页面复制共享链接。

## 如何让网址不含平台账号名

页面显示名称是 **Supervision Circle**，代码包名称是 `supervisioncircle`。这些名称不会决定托管域名。

Sites 可以修改网站网址的前缀；平台自动附加的账号域名与前缀是两部分。现有 Sites 工具支持绑定自定义域名，但没有修改账号域名的接口。

如果已有自己控制的域名，可以给同一个 Sites 项目绑定一个子域名，按平台返回的记录配置 DNS，并等待域名与 HTTPS 验证成功。保持同一 Sites 项目和 D1，通常无需搬迁投票数据。验证后从新域名进入管理页，重新复制共享链接；完整路径与链接片段需要保留。

更换域名会改变浏览器存储的来源，因此旧域名下记住的姓名或管理入口不会自动迁移。先保存完整管理链接，再进入新地址。

## 如果没有域名

可以考虑部署到自己账号下的 Cloudflare Workers，并使用其提供的地址。这个应用已经基于 Workers 运行环境和 D1，但仍需要单独连接 Cloudflare 账号、创建 D1、配置构建与部署、迁移已有数据并验证。仓库上传完成不表示这些步骤已完成。

GitHub Pages 只能托管静态部分，无法直接运行本项目的 D1 服务端接口，因此不能单独替代当前托管。网址缩短服务也不解决实际页面地址中出现平台账号名的问题。

在新的干净地址验证成功之前，不应把旧平台域名当作已满足命名要求的最终共享链接。

# 修改与维护

## 不改代码也能做的事

在管理页面调整姓名、会议名称、默认时区、每月截止时间和候选时段。这些是保存在服务器的数据，修改后不需要重新发布程序。

## 让 Codex 帮你修改

把 `yelidifei/supervisioncircle` 添加为项目并打开，可以直接说明想改什么，例如：

> 在 supervisioncircle 中把截止时间提示改得更醒目，手机也要清楚。保留现有投票数据，检查后更新现有 Cloudflare Workers 网站。网站名称仍为 Supervision Circle，不在网址或文案中添加其他账号名。

仅推送 GitHub 不会更新线上版本。想同步上线时明确说“更新现有 Cloudflare 网站”。维护时复用名为 `supervisioncircle` 的 Worker 和 D1 数据库，不要新建空数据库代替已有数据库。`.openai/hosting.json` 是旧 Sites 存档的关联，不是当前生产入口。

## 本地运行

建议使用 Node.js 24 和 pnpm。安装步骤见仓库首页。本地数据库创建完成后，启动 `pnpm dev`；本地填写的是测试数据，不会改线上数据。

`pnpm-workspace.yaml` 已列出必要的依赖构建许可，安装时保留该文件与 `pnpm-lock.yaml`。不要把本机的 `node_modules` 复制到 GitHub。

## 去哪里改

| 需求 | 文件 |
| --- | --- |
| 首次创建小组的页面 | `app/page.tsx` |
| 导师与管理界面、按钮、英文邮件文案 | `components/meeting-app.tsx` |
| 页面布局、颜色、手机样式 | `app/workspace.css`、`app/globals.css` |
| 页签标题和页面 metadata | `app/layout.tsx` |
| 四种回复、推荐排序、时间校验、业务状态 | `lib/domain.ts` |
| 权限、D1 保存、并发冲突处理 | `lib/server.ts` |
| 浏览器 API 请求与共享链接派生 | `lib/client.ts` |
| API 路由 | `app/api/circles/` |
| 数据库表结构 | `db/schema.ts` |
| 数据库迁移 | `drizzle/` |
| 当前 Cloudflare 部署配置模板 | `wrangler.cloudflare.example.json` |
| 本机的实际 Cloudflare 绑定（不提交） | `wrangler.cloudflare.json` |
| 旧 Sites 存档关联 | `.openai/hosting.json` |

若要把 45 分钟改成其他时长，或改变人数，必须同时检查业务校验、界面、说明和测试；本版把五人和 45 分钟作为明确产品规则，不能只改一处显示文字。

## 检查改动

```sh
pnpm typecheck
pnpm test
pnpm build
```

涉及保存、权限、多人协作或投票状态的修改，还要启动本地开发服务器，在另一个终端执行：

```sh
pnpm test:integration
```

领域测试覆盖时间边界和夏令时、推荐分类、补充候选、权限、同一格冲突、选定和已发送状态。集成测试通过真实本地 API 和 D1 验证五个并发客户端、回复隔离、权限和状态转换。

修改交互后，在电脑与手机宽度下检查选择姓名、保存回复、修改回复、补充时间的完整流程。

## 提交 GitHub 与重新上线

先查看自己改了哪些文件，再提交并推送到本仓库。建议较大改动使用独立分支和 Pull Request。

当前发布流程：运行检查，然后执行 `pnpm deploy:cloudflare`。这个命令会先构建，再通过 Wrangler 发布到既有 Worker。GitHub 保存源码，Cloudflare 运行已发布版本；本版没有配置 GitHub 自动部署。

数据库结构变化时运行 `pnpm db:generate`，检查并应用新迁移，再发布。已经在线上执行过的迁移不可重写。常规界面更新不会清空数据；不要在维护中删除或替换数据库。旧站的 `CIRCLE_READ_ONLY=true` 应保持开启。

## 不应提交的内容

`.gitignore` 排除了环境文件、本地数据库、依赖和构建产物。仍需手动检查，确保没有管理链接、真实投票导出、访问令牌或测试凭据。网站项目 ID 是关联配置，不是访问密钥。

源码备份不等于数据备份。现有业务数据在 D1 中；更换托管平台前需要单独规划数据导出和恢复，不能只复制 GitHub 仓库。
